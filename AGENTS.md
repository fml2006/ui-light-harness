# UI Light

Activar cuando el usuario pida UI Light o una actualización visual de una UI existente.
Un screenshot por sí solo no convierte un bug funcional en tarea visual.

1. Leer `harness/ui/UI-LIGHT.md` y `harness/ui/REFERENCE-POLICY.md`.
2. Leer el mapa de `harness/ui/EXISTING-UI.md`; conservar la marca del sitio actual.
   Consultar fuentes de marca y patrones solo para los atributos afectados.
3. Un agente, contexto local al cambio, sin delegación ni cambios automáticos de modelo.
4. Máximo dos lotes de edición y validación; conservar el contador al retomar.
5. Si el trabajo deja de ser visual, entregar evidencia y escalar; no ampliar alcance.
6. DONE requiere capturas reales y comprobación del comportamiento afectado.

No comprar, recargar ni activar servicios pagos. El consumo requiere autorización
explícita con alcance, máximo de intentos y tope total. Por defecto: cero consumo.
Las instrucciones globales del equipo y los permisos de entrega siguen vigentes.
